## 1.1 DB 호출 : 좋아요, 스크랩 조회시 불필요한 쿼리 작성으로 성능 저하

### 1.1.1 문제 상황
- 게시글 20개 조회 시 게시글마다 countLike, countScrap을 호출하여 최대 40번의 추가 쿼리가 발생하는 문제를 발견
### 1.1.2 원인 분석
- Service의 for문에서 게시글별로 좋아요와 스크랩 여부를 건별 조회하는 곳의 문제
### 1.1.3 해결 방안
- PostMapper.xml의 조회 쿼리에 EXISTS 서브쿼리를 추가하여 liked, scrapped 값을 한 번에 조회하고 Post에 매핑하는 방향으로 수정

## 1.2 구글 인증: Google OAuth redirect_uri


### 1.2.1 문제 상황
- Google Console에 https 콜백을 등록했는데도 OAuth 로그인이 실패
### 1.2.2 원인 분석
- Nginx가 HTTPS를 종료한 뒤 HTTP로 넘겨, Spring이 redirect_uri를 http로 생성함
### 1.2.3 해결 방안
- Nginx에서 X-Forwarded-Proto를 전달
- Spring Boot에서 forward-headers-strategy=framework를 설정하여 HTTPS 정보를 올바르게 인식하도록 수정하여 해결

---

## 1.3 환불: 결제 데이터 삭제로 인한 데이터 일관성 문제

### 1.3.1 문제 상황
- 환불 후 결제 데이터를 삭제하면서 발생한 이력 관리 문제

### 1.3.2 원인 분석
- 환불 완료 후 결제 및 구매 데이터를 삭제하는 방식은 결제 이력이 사라지고 재구매 처리에도 문제가 발생

### 1.3.3 해결 방안
- 데이터를 삭제하지 않고 결제 상태와 구매 상태만 변경하도록 수정하여 환불 이력을 보존하여 해결

## 1.4 관리자: 회원 관리에서의 회원 강퇴 처리

### 1.4.1 문제 상황
- 회원 삭제 시 참조 무결성 문제
### 1.4.2 원인 분석
- 관리자가 회원 강퇴를 했을 때 회원을 삭제하려 했으나 이 회원의 email로 재가입을 막아야 하는 조건, 해당 회원의 글과 댓글도 같이 삭제해야하는 참조 무결성을 고려해야 하는 등 문제 발생

### 1.4.3 해결 방안
- 회원을 삭제하는 대신, member table에 status컬럼을 추가하여 활동을 정지시키는 방향 구현. 활동이 정지된 사람은 게시글 및 댓글을 작성, 수정 불가하도록 만드는 등 기능을 제한

---

## 1.5 팔로우: 팔로워 목록 조회 API 개선

### 1.5.1 문제 상황
- 자신의 팔로워 목록만 조회할 수 있어 다른 회원의 팔로워 목록 조회가 불가능한 문제 발생

### 1.5.2 원인 분석
- 현재 로그인한 사용자의 ID만 가져오는 방식으로 구현되어 있었기 때문
### 1.5.3 해결 방안
- 프론트엔드에서 회원의 ID를 전달받는 방식으로 API를 변경
- @AuthenticationPrincipal 대신 @PathVariable을 사용
